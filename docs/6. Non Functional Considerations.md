# Non Functional Considerations

## Reliability

- Auction-won handler idempotent on `auctionId` (`OrderService.createOrder` find-or-create).
- Outbox-style notification persistence before STOMP fan-out reduces lost messages on broker blips.

## Security

- Dispute APIs restricted to buyer/seller roles via gateway headers.
- STOMP subscription isolation mandatory for notification privacy — [11. Keamanan stomp.md](./11. Keamanan stomp.md).
- Push subscriptions bound to authenticated user id.

## Performance

- STOMP public auction topics may have many subscribers; avoid large payloads in messages.
- Notification list paginated in REST API.

## Usability

- Multi-channel notifications (in-app + email + push) with preference controller.
- Frontend hooks: `src/hooks/useNotificationRealtime.ts`, `useWebSocket.ts`.

## Compliance

- Dispute audit fields on `BidmartOrder` (`disputeReason`, `sellerDisputeResponse`, `disputeWinner`).
