# STOMP / WebSocket Security Model

## Overview

BidMart order-and-notification service exposes SockJS STOMP at `/ws/notifications`. Messages use **topic-based routing** with optional **user-specific** destinations.

## Destination layout

| Destination pattern | Visibility | Publisher |
|---------------------|------------|-----------|
| `/topic/auctions` | Public (any connected client) | `AuctionRealtimeService` |
| `/topic/auctions/{auctionId}` | Public | `AuctionRealtimeService` |
| `/topic/listings/{listingId}` | Public | `AuctionRealtimeService` |
| `/topic/sellers/{sellerId}/auctions` | Public (seller-scoped broadcast) | `AuctionRealtimeService` |
| `/topic/notifications/users/{userId}` | **Private** — subscriber must match JWT `sub` | `NotificationService` |
| `/user/{userId}/queue/notifications` | **Private** — Spring user destination | `NotificationService` |

## Authentication

1. Client opens SockJS to `/ws/notifications` (through API Gateway sticky route).
2. On STOMP `CONNECT`, client sends native header `Authorization: Bearer <access-jwt>`.
3. `NotificationStompAuthorizationInterceptor` parses JWT (`type=access`), sets `Principal.name = subject` (user id).

Without a valid token, CONNECT succeeds but **private** destinations cannot be subscribed safely; subscription to another user's notification topic is rejected.

## Authorization (subscription isolation)

On `SUBSCRIBE`, the interceptor checks:

- `/topic/notifications/users/{userId}` → `userId` must equal `Principal.getName()`
- `/user/{userId}/queue/notifications` → same rule
- `/topic/auctions*` and listing/seller auction topics → allowed (public auction feed)

Violations throw `IllegalArgumentException` (STOMP ERROR to client).

## Gateway alignment

HTTP APIs use trusted `X-User-Id` from `bidmart-infrastructure` JWT filter. WebSocket path is optionally authenticated at gateway; **application-level JWT on CONNECT** is the source of truth for STOMP Principal.

## Tests

- `NotificationStompAuthorizationInterceptorTest` — subscription isolation matrix
- `NotificationServiceTest` — verifies publish paths for user queue + topic

## Future hardening

- Require JWT on CONNECT for production (reject anonymous private subscriptions entirely)
- Rate-limit SUBSCRIBE per session
- Move notification topics to `/user/queue/...` only and deprecate public `/topic/notifications/users/{id}` pattern
