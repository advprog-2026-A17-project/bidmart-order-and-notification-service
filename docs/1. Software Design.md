# Software Design

## Layering

- **Controllers:** `controller/OrderController.java`, `NotificationController.java`, `PushSubscriptionController.java`, `NotificationPreferenceController.java`
- **Services:** `service/OrderService.java`, `service/NotificationService.java`, `service/AuctionRealtimeService.java`
- **Clients:** `client/WalletClient.java` — refund on dispute buyer win
- **Events:** `event/AuthEventConsumer.java`, auction consumers
- **STOMP:** `config/NotificationStompAuthorizationInterceptor.java`, WebSocket config

## SOLID

- **SRP:** `OrderService` (fulfillment/disputes) vs `NotificationService` (delivery channels) vs `PushSubscriptionService`.
- **OCP:** New notification channels implement `NotificationEmailSender` / `PushNotificationSender` without changing core notification persistence.
- **LSP:** `WebPushNotificationSender` and `LogPushNotificationSender` interchangeable via `PushNotificationSender` interface.
- **ISP:** Narrow sender interfaces (`sendNotificationEmail`, `sendPush`).
- **DIP:** `OrderService` depends on `WalletClient` abstraction for refunds.

## Patterns (≥3)

### 1. Repository

`repository/OrderRepository.java`, notification repositories.

### 2. Strategy / conditional beans

- `WebPushNotificationSender` vs `LogPushNotificationSender` (`@ConditionalOnMissingBean`)
- `SmtpNotificationEmailSender` vs `LogNotificationEmailSender`

### 3. Domain state machine

`BidmartOrder` methods: `openDispute`, `confirmReceipt`, status transitions in `model/OrderStatus.java`.

### 4. Observer / messaging

- `AuthEventConsumer` reacts to auth registration for welcome notifications.
- STOMP publish from `NotificationService` / `AuctionRealtimeService`.

### 5. Interceptor (STOMP security)

`NotificationStompAuthorizationInterceptor` — subscription isolation per [11. Keamanan stomp.md](./11. Keamanan stomp.md).

## Dispute flow (design)

| Step | Actor | Code |
|------|-------|------|
| Open | Buyer | `OrderService.openDispute` → `notifyOrderDisputed` |
| Respond | Seller | `OrderService.respondToDispute` |
| Resolve | Admin/system | `OrderService.resolveDispute` + `WalletClient` refund if buyer wins |
